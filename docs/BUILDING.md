# Building Open MaxView

## Requirements

* GNU make and a POSIX host shell;
* Open Watcom, defaulting to `/opt/watcom`;
* an Open 386MAX checkout, defaulting to `/home/mario/mars/386MAX`;
* the open-source `linux/bin/jwasm` and `linux/bin/jwlink` embedded in that
  Open 386MAX tree;
* a host C89 compiler and Python 3 for host tests;
* DOSBox for `make test-dos`.
* Pandoc and LuaLaTeX for `make books` (the runtime build does not need them).

The project intentionally uses the same Open Watcom/JWasm/JWlink toolchain as
Open 386MAX. NASM is not part of the build.

## Commands

```sh
make
make package
make setup-package
make test
make test-dos
make books
make clean
```

Override tool locations without editing the makefile:

```sh
make WATCOM=/path/to/watcom MAXROOT=/path/to/386MAX
```

`make` writes DOS binaries, maps and copied data to `build/`. C sources are
compiled for 16-bit small-model DOS with Open Watcom. Assembly sources use
JWasm's MASM-compatible mode and JWlink creates COM and DOS EXE images.

`make package` rebuilds `build/OpenMaxView/` as installation media. It
contains the installer, runtime programs, default data files, README and GPL
license. Build objects, maps and test-only probes are not copied there.

`make setup-package` additionally builds the three documentation books and
creates a distributable set below `build/releases/<version>/`: a
deterministic DOS ZIP containing the complete `OpenMaxView/`
installation-media directory, the
developer HTML book, the user PDF and EPUB, plus `SHA256SUMS.txt`. The archive
name uses the single token in `VERSION`. Set `SOURCE_DATE_EPOCH` when a release
needs a timestamp other than the deterministic 1980 default.

`make release-check` starts from a clean build, runs host and DOSBox tests and
then creates those release artifacts. It is the release-candidate command;
the remaining real-machine and interactive checks are listed in
`TESTING.TXT`.

## Documentation books

The book builder consumes the Markdown sources and their linked SVG diagrams:

```sh
make book-html  # build/books/OpenMaxView-Developer.html
make book-pdf   # build/books/OpenMaxView-User.pdf
make book-epub  # build/books/OpenMaxView-User.epub
make books      # all three products
```

The developer HTML book is self-contained: its 386MAX-inspired stylesheet and
images are embedded so it can be copied or opened without the source tree. It
combines the programming, API, architecture, build, test and development
material, including the clearly deferred 2.x network design. The user PDF
applies the same blue, gray, cyan and red visual vocabulary, starts with the
quick-start guide, and combines daily operation, tools, configuration, BBS
planning and troubleshooting in A4 book format.

The EPUB contains the same user chapters and diagrams as the PDF, but uses a
reflowable E-reader stylesheet rather than fixed A4 pages. Its navigation
document and chapter splits are generated by Pandoc.

Use `python3 tools/build_books.py --check` for a fast source and local-link
check without Pandoc. `--output directory` changes the destination and
`--format developer-html`, `--format user-pdf` or `--format user-epub` builds
one product.

## Reproducible inputs

Quarterdeck media is not a build input. `/home/mario/Iso/dos/` or any other
local reference-media location must never appear in a make dependency or
package. The only external source dependency used by the DOS runtime design
is the separately maintained Open 386MAX project.

Open 386MAX's `9x` branch is the development target for the backend contract.
Milestone 0.8 validates private ABI 1.0 and QPI functions `03h` and `07h`. Its
developer probe also tests a bounded `04h`/`06h`/`05h` allocate, clone and
release cycle plus verified `08h` switches to the clone and back to the
captured root. In the clone it exercises a four-entry `09h`/`0Ah` mapping
table backed by a four-page `04h` private data pool, read-back, partial and full
commit, persistence across a verified root/clone switch, non-sequential
restoration, pool exhaustion and guards against leaving an incompletely
committed table or releasing resources out of order.
Context switching is not yet performed by the shipped launcher, even though
the guarded backend wrapper and current Open 386MAX provide it.
